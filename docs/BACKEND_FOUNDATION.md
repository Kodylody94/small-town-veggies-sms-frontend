# Protected Backend Foundation

## Status

This stage provides a secure, testable backend boundary without connecting production infrastructure.

The following remain intentionally disabled or unconfigured:

- Production database adapter
- Durable session store
- Durable rate-limit store
- Durable idempotency store
- Live frontend mutations
- Broadcast and reminder delivery
- Android SMS gateway
- Production deployment

Production runtime fails closed when a required durable adapter is missing.

## Architecture

The Vercel function entrypoint is `api/router.js`. It delegates to a dependency-injected router in `api/_lib/router.js`.

Dependency injection keeps request security and business behavior testable without provisioning a database. The runtime uses:

- `UnconfiguredRepository`
- `UnconfiguredSessionStore`
- `UnconfiguredRateLimiter`
- `UnconfiguredIdempotencyStore`

when `BACKEND_RUNTIME_MODE=production`.

Local and automated tests may use memory adapters. Those adapters are not approved for live data because serverless instances do not share durable memory.

## Request security order

Protected requests are processed in this order:

1. Assign an opaque request ID.
2. Apply `Cache-Control: no-store`.
3. Load fail-closed backend configuration.
4. Apply exact-origin credentialed CORS.
5. Validate preflight requests against a narrow method and header allowlist.
6. Validate the signed administrator session cookie.
7. Verify that the session remains active in the server-side session store.
8. For mutations, validate:
   - exact `Origin`
   - Fetch Metadata site context
   - `Content-Type: application/json`
   - `X-Small-Town-Veggies-Request: dashboard`
   - session-bound `X-CSRF-Token`
   - `Idempotency-Key` where the operation can change business data
9. Apply rate limiting.
10. Validate request fields.
11. Execute the repository operation.
12. Write a structured audit event.
13. Return a normalized JSON envelope.

## Authentication

The foundation currently supports one administrator credential supplied through a server-only scrypt hash.

Generate the hash locally:

```bash
npm run admin:hash -- "a-long-unique-password"
```

Store the output in `ADMIN_PASSWORD_HASH`. Never place the raw password or hash in a `VITE_*` variable.

A successful login creates:

- a signed `HttpOnly` session cookie
- a random server-side session identifier
- a session-bound CSRF token returned in the JSON response
- a durable-session requirement for production

Logout revokes the server-side session identifier and expires the browser cookie.

## Routes

| Method | Route | Current behavior |
| --- | --- | --- |
| `GET` | `/api/health` | Reports configuration and disabled integrations without exposing secrets |
| `POST` | `/api/auth/login` | Verifies the scrypt password and creates a revocable session |
| `GET` | `/api/auth/session` | Validates the cookie and returns the CSRF token and expiration |
| `POST` | `/api/auth/logout` | Revokes the server-side session and expires the cookie |
| `GET` | `/api/orders` | Requires authentication; repository remains unconfigured in production |
| `GET` | `/api/customers` | Requires authentication; repository remains unconfigured in production |
| `GET` | `/api/products` | Requires authentication; repository remains unconfigured in production |
| `POST` | `/api/orders/{id}/confirm` | Protected, validated, rate-limited, and idempotent |
| `POST` | `/api/orders/{id}/ready` | Protected, validated, rate-limited, and idempotent |
| `POST` | `/api/orders/{id}/pickup` | Protected, validated, rate-limited, and idempotent |
| `POST` | `/api/products` | Protected, validated, rate-limited, and idempotent |
| `POST` | `/api/broadcasts` | Always returns `MESSAGING_DISABLED` |
| `POST` | `/api/reminders` | Always returns `MESSAGING_DISABLED` |

## Database migration

`database/migrations/001_backend_foundation.sql` defines PostgreSQL tables for:

- administrators
- revocable administrator sessions
- customers and consent state
- products
- orders and order items
- idempotency records
- rate-limit buckets
- audit events

The migration has not been applied anywhere. Applying it and connecting a provider require a separate approval.

## Environment variables

| Variable | Purpose |
| --- | --- |
| `APP_ORIGIN` | Exact dashboard origin accepted by CORS and mutation checks |
| `SESSION_SECRET` | HMAC secret with at least 32 characters |
| `ADMIN_PASSWORD_HASH` | Scrypt password hash generated by the repository script |
| `SESSION_TTL_SECONDS` | Session lifetime; defaults to eight hours |
| `ALLOW_SAME_SITE_REQUESTS` | Explicitly permits reviewed same-site requests when `true` |
| `BACKEND_RUNTIME_MODE` | `development` for local memory adapters or `production` for fail-closed durable-adapter requirements |
| `DATABASE_URL` | Reserved for the separately approved database-adapter stage |

## Verification

Run:

```bash
npm run lint
npm test
npm run build
npm run test:e2e
```

The backend contract suite covers:

- health behavior without configuration
- origin rejection
- secure cookie attributes
- session authentication
- server-side logout revocation
- authenticated collection envelopes
- CSRF rejection
- idempotent order transitions
- invalid transition rejection
- field-level product validation errors
- messaging shutdown
- narrow preflight responses
